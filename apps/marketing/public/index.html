A motion studio your AI can direct.

Motion MCP is a Streamable HTTP MCP server. Your host model calls motion_create with a brief and gets back a rendered, web-optimized MP4, from Claude, ChatGPT, Pi or any other MCP client.

01

How it works

Each step goes to the cheapest thing that can do it well. Judgment goes to a model; everything mechanical goes to code.

  1. A

    Opus directs

    Creative director

    Opus writes the creative spec, the taste packet and scene architecture, in one structured call, and critiques creative issues. It never writes HyperFrames HTML.

  2. B

    Jev routes

    Decision layer

    Jev answers typed questions about where work should go: a mechanical patch, a new asset, a render retry or an Opus critique. Every escalation is a traced decision. Jev never generates content.

  3. C

    Pi and cheap workers build

    Scene builders

    A deterministic compiler turns Motion IR into scenes. Only scenes that need bespoke code go to Pi, driving a cheap coder model (deepseek/deepseek-v4-flash by default).

  4. D

    HyperFrames renders

    Render and finish

    HyperFrames lints, checks, snapshots and renders in a pinned Linux container. FFmpeg finishes the file: faststart, yuv420p and loudness normalization when audio is present.

Two director modes. You choose, per call.

The server never infers the mode from model names. Pass directorMode on each call, or let the workspace default apply.

host-opus

Your host is the director.

The calling model writes the CreativeSpec against the JSON Schema that motion_inspect returns. A valid spec skips the internal director entirely; an invalid one returns validation issues with no Opus spend.

Use when your host is already a frontier model, so a second Opus call would pay twice for the same taste.

internal-opus

Motion MCP directs.

Send only a brief. Motion MCP calls Opus through OpenRouter for creative direction and critique, gated by Jev and bounded by your budget.

Use when the host is a small model or a script, or you want the platform’s direction.

02

Eight tools. That’s the whole surface.

New capability lands as arguments on these tools, never as new tools. Long work returns a jobId right away; poll motion_get_project for progress.

motion_create
Start a video from a brief, or from a host-written creative spec. Returns a project and a job.
motion_edit
Revise with a plain-language instruction or typed scene patches. Only the affected scenes are touched.
motion_inspect
The director handshake: schema, director modes, pricing and limits. Also inspects projects, scenes and styles.
motion_render
Render a draft preview, or a final once lint and check pass. MP4 or WebM.
motion_search
Search styles, shot patterns, recipes, registry blocks, projects and assets.
motion_get_project
Poll job state, stage and progress. Include versions, renders, usage or a cost trace.
motion_list_projects
Page through the projects in your workspace.
motion_publish
Publish a finished final render at a stable share URL, unlisted or public.

03

Connect in one block.

Add the endpoint to any MCP client that speaks Streamable HTTP. Every request carries a per-workspace API key as a bearer token.

  1. Create an API key in the dashboard.
  2. Paste the config and replace the placeholder.
  3. Ask your model to call motion_inspect, then motion_create.
mcp.json 
{
  "mcpServers": {
    "motion": {
      "type": "http",
      "url": "https://app.motion.digitop.ai/mcp",
      "headers": {
        "Authorization": "Bearer mmcp_YOUR_API_KEY"
      }
    }
  }
}

04

Frontier tokens only for taste.

Before every model call, one question: does this step need taste? If it is mechanical, code does it. If it needs judgment, the cheapest model that can make that judgment does it. Opus is reserved for creative direction and critique.

  • Deterministic first. Normalizing, compiling, linting, checks and FFmpeg finishing are code, not model calls.
  • Respect a host spec. A valid host-opus spec skips the internal director and its cost.
  • Scene isolation. Critique, patches and rebuilds touch only the affected scenes.
  • Snapshot before render. Checks run on contact sheets. Previews render at draft quality; the final renders once.
  • Bounded budgets. Set budgetCredits per job. A job that would overspend stops and reports the shortfall.

Open source, MIT.
Host it yourself.

Run the whole stack on your own machine or VPS with your own provider keys. Renders run in a pinned Linux container, and billing can be turned off entirely when you self-host.

Motion MCP stands on HyperFrames, Pi and multix rather than re-implementing them. What it adds is the taste layer: a director, a renderer-neutral Motion IR and cost-aware routing where every decision is traced.
